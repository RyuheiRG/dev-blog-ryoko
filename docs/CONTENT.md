## 7. Plantilla de case study

Cada proyecto debe seguir esta estructura:

1. **Ficha**
   - Rol, equipo, año, stack, estado, links.
2. **Contexto**
   - Qué es, para quién, por qué existió.
3. **Problema**
   - Qué había que resolver. Sin solución todavía.
4. **Restricciones**
   - Tiempo, materia, equipo, stack, infraestructura, presupuesto.
5. **Decisiones**
   - 3–5 decisiones con su tradeoff.
   - Formato: decisión → por qué → qué se sacrificó.
6. **Arquitectura**
   - Diagrama y explicación de capas.
7. **Implementación**
   - Capturas, fragmentos de código, detalles interesantes.
8. **Resultado**
   - Qué funciona, qué no, demo, pruebas.
9. **Aprendizajes**
   - 3 bullets concretos.
10. **Qué haría diferente**
    - 2–3 bullets honestos.

Reglas:

- No pegar el README.
- No inventar métricas.
- Si no hay screenshot, crear un diagrama o una portada tipográfica.
- Mencionar el equipo cuando sea colaborativo.
- No revelar secretos, tokens ni datos personales.

## 8. Case studies: datos reales

### 8.1 Frame-Data-Bayes

**Ficha**

| Campo | Valor |
|---|---|
| Año | 2026 |
| Rol | Desarrollo, datos, UI |
| Equipo | Individual |
| Stack | Python 3.12+, Pandas, NumPy, Scikit-Learn, Streamlit, Matplotlib, Seaborn |
| Estado | Funcional, local |
| `publish_status` | `published` |
| `lifecycle_status` | `live` |
| Repo | `https://github.com/RyuheiRG/frame-data-bayes` |
| Demo | No disponible |

**Resumen**

Motor de análisis probabilístico y clasificación estadística bajo Clean Code y Zero Trust. Trata cada CSV como un entorno hostil: valida la superficie de entrada, detecta tipos de datos de forma determinística y aplica inferencia bayesiana para predecir anomalías.

**Problema**

Los datasets CSV llegan sucios, con tipos inconsistentes y columnas inesperadas. Un análisis estadístico confiable necesita validar antes de modelar.

**Decisiones**

- Ingesta segura con validación de integridad y manejo de excepciones.
- Detección automática de vectores numéricos, categóricos, temporales y binarios.
- Implementación explícita del Teorema de Bayes.
- Gaussian Naïve Bayes para clasificación de anomalías.
- Visualizaciones de histogramas, series temporales y matrices de confusión.

**Diagrama sugerido**

```text
CSV → Validación → Detección de tipos → Limpieza → Bayes → Clasificación → Visualización
```

**Capturas necesarias**

- Panel de ingesta.
- Panel EDA.
- Panel Bayes.
- Matriz de confusión.
- Histograma / serie temporal.

Si no se pueden generar, usar un diagrama de pipeline y una portada tipográfica con la fórmula de Bayes.

**Aprendizajes**

- Validar antes de modelar ahorra horas de debugging.
- La interpretabilidad importa más que la accuracy en un contexto académico.
- Un pipeline claro se puede explicar; un notebook no.

### 8.2 SecureUP

**Ficha**

| Campo | Valor |
|---|---|
| Año | 2026 |
| Rol | Desarrollo Android |
| Equipo | Individual |
| Stack | Kotlin 2.2.10, Jetpack Compose, Material 3, MVVM, Room 2.8.5, Retrofit 2.12.0, CameraX 1.6.2, ML Kit 17.3.0 |
| Estado | Funcional; backend propio pendiente |
| `publish_status` | `published` |
| `lifecycle_status` | `wip` |
| Repo | `https://github.com/RyuheiRG/SecureUP` (rama `develop`) |
| Demo | APK debug; no publicada |

**Resumen**

Aplicación Android de seguridad digital personal: verifica contraseñas filtradas sin exponerlas, escanea códigos QR y analiza la URL antes de permitir abrirla, y guarda el historial de escaneos en el dispositivo.

**Problema**

Las personas reutilizan contraseñas y abren enlaces sin verificar. Una app puede ayudar sin convertirse en un recolector de credenciales.

**Decisiones**

- HIBP Pwned Passwords con k-anonimato: solo se envía el prefijo SHA-1 de 5 caracteres.
- La contraseña completa nunca sale del dispositivo.
- Análisis local de URLs con reglas: esquema, HTTPS, IP como host, punycode, user-info, acortadores, longitud.
- Solo las URLs seguras ofrecen abrir en el navegador.
- Room para historial; PDF con `PdfDocument` y SAF.
- MVVM: UI → ViewModel → Repository → Room/Retrofit.
- 71 pruebas unitarias, lint 0 errores y 22 advertencias.

**Capturas disponibles**

- `docs/evidencias/01-login.png`
- `docs/evidencias/02-brecha-expuesta.png`
- `docs/evidencias/03-qr-seguro.png`
- `docs/evidencias/04-qr-peligroso.png`
- `docs/evidencias/05-inicio-score.png`
- `docs/evidencias/06-historial.png`
- `docs/evidencias/08-splash.png`

**Diagrama sugerido**

```text
Compose UI → ViewModel (StateFlow) → Repository → Room / Retrofit / ML Kit
```

**Aprendizajes**

- El k-anonimato es una decisión de diseño, no solo de criptografía.
- El historial local puede dar valor sin backend.
- La seguridad de una app también está en lo que no hace.

**Limitaciones honestas**

- El backend propio aún no existe; el login usa un repositorio simulado.
- La bóveda de contraseñas está pospuesta.
- El análisis de URLs es heurístico, no un servicio de reputación.

### 8.3 Vaca Cúbica

**Ficha**

| Campo | Valor |
|---|---|
| Año | 2026 |
| Rol | Full stack |
| Equipo | Ricardo Reyes Gómez, Erick de Jesús Nafate Nafate, Braulio Alejandro Jiménez |
| Stack | React 18, Vite, pnpm, FastAPI, Uvicorn, SQLAlchemy async, MySQL 8.4, AWS EC2 + RDS |
| Estado | Funcional; deploy en Vercel + AWS |
| `publish_status` | `published` |
| `lifecycle_status` | `live` |
| Repo | `https://github.com/RyuheiRG/vaca-cubica` |
| Demo | `https://vaca-cubica.vercel.app` |

**Resumen**

Sistema de Gestión Bovina (S.G.B.) con arquitectura cliente-servidor en monorepositorio. Frontend React + Vite; backend FastAPI + MySQL; despliegue en AWS con RDS aislado en VPC y EC2 como nodo de cómputo.

**Problema**

Gestionar información bovina en un contexto académico, con una arquitectura que no fuera un CRUD improvisado.

**Decisiones**

- Monorepo con frontend y backend separados.
- FastAPI + SQLAlchemy async + asyncmy.
- MySQL 8.4 local con DBngin; RDS en producción.
- RDS sin acceso público, solo desde la VPC.
- EC2 como bastion host y nodo de cómputo.
- Pydantic aborta el arranque si faltan variables críticas.
- Autenticación con JWT y `SECRET_KEY`.

**Diagrama sugerido**

```text
React + Vite → FastAPI → SQLAlchemy → MySQL
                         │
                         └── AWS EC2 → Amazon RDS (VPC privada)
```

**Capturas necesarias**

- Login.
- Dashboard.
- Gestión de ganado.
- Arquitectura AWS.
- Base de datos.

**Aprendizajes**

- La separación cliente-servidor se vuelve tangible cuando hay que desplegar.
- La seguridad de infraestructura no es opcional: RDS privado, security groups, secrets.
- Un monorepo ordena el trabajo en equipo, pero exige disciplina.
